Instructions and Workflow

Everything below covers the complete process, start to finish: recording a singing in Capture, then reviewing and preparing finished minutes in Compile.

Pre-Release

EZ Minutes is still in testing. Any and all feedback is welcome — please use with caution, and keep a backup of anything important. Reach the developer, Kevin of SingLoud.org, at sacredharpbiblio@gmail.com.

Quick Start

  1. Open Capture before the event.
  2. Record the event and its sessions.
  3. Save and download the EZ Minutes CSV file.
  4. Open Compile after the event.
  5. Review the imported rows and correct any flagged items.
  6. Choose the desired terminology and export format.
  7. Preview and export the finished result.

Preparing Before the Event

  • EZ Minutes is built for a laptop, desktop computer, or a tablet with a physical keyboard — it isn't designed for phone-sized screens.
  • Open Capture ahead of time, ideally before you arrive, so it's already loaded and ready. It's a single file with no install step.
  • Capture works fully offline — no internet connection is required once the page is open, and nothing about logging songs depends on a network connection at all.
  • On the welcome screen, choose Start New Singing to begin a fresh event.
  • Fill in Event, Date, Location, and — if known — the Officers & Roles fields (Chair, Vice-Chair, Secretary, Treasurer, Arranger(s), Chaplain, Memorial Lesson Leader). None of these are required to start logging songs, but filling them in early means Compile won't need to guess later.
  • If it's useful, download an early backup CSV once the first few songs are in, just to confirm the whole save/export path works on this device before it matters.
Sacred Harp business-session officer elections are usually a ceremonial reconfirmation of whoever is already serving, not a new appointment. If that's the case, fill in Officers & Roles with the actual presiding officers at the very start of logging, rather than waiting for the business session to make it "official."

Recording with Capture

  • For each song: type the Leader, then the Page (e.g. 123, 45t, 45b for a top/bottom page), and press Enter — no button needed.
  • The song title looks itself up automatically from whichever songbook is selected. If a page could mean two different songs, Capture asks you to specify top or bottom rather than guessing. If a page doesn't exist in the book's index, it asks you to confirm before adding it, so a typo doesn't get logged as if it were real.
  • Multiple leaders on one song can be entered comma-separated in the Leader field.
  • Use Recess / Lunch / Announcements to mark breaks.
  • Tag a song Call Back (the leader who brings the class back together after a break), Memorial, or Special as it applies.
  • To correct a recent entry, tap it in the log to edit it in place — the same page/leader/duplicate checks apply to an edit as to a new entry.

Sessions, Days, and Locations

An event in EZ Minutes can span more than one session — a second day of a convention, a change of venue, or any other clearly distinct segment of the same overall event. This is different from starting a whole new singing:

  • Start New Singing begins an entirely new event and a new file. Use this when you're done with one singing and moving on to a completely different one.
  • Start New Session stays inside the same event and the same file. Use this for a new day, a changed location, or a distinct segment of the same convention.

Tapping Start New Session reopens the setup fields so you can update the Date and/or Location, add a session label if you like (e.g. "Day 2"), and update Officers & Roles if anything genuinely differs for this session — then confirm. Nothing already logged changes; everything from that point forward carries the new details.

A session can carry its own:

  • date
  • location
  • session label
  • officers, only where they actually differ from the event's usual officers

Saving and Backups

  • Capture saves to this browser automatically as you go — no action needed. A status line shows Saved locally at [time], or a clear warning if local saving isn't working on this device.
  • If you accidentally refresh or close the tab, reopening Capture on the same device and browser restores where you left off.
  • Local saving alone isn't a substitute for a real backup — download or copy the CSV during the event as well, and definitely at the end. That downloaded file is what actually moves into Compile afterward.
  • An optional automatic periodic backup download exists (off by default) — turn it on if you'd like an extra copy saved to your Downloads folder every few minutes. It's a bonus, not a replacement for downloading the final file yourself.

Opening the File in Compile

  • On the Import tab, choose the CSV file Capture saved — either the final download, or an autosave copy if that's all you have.
  • Compile checks the file's schema version. A mismatch doesn't block the import outright, but it's flagged clearly so you know to double-check the result rather than assume everything came through correctly.
  • Event Details, Roles, and the Song List all auto-fill from what Capture recorded. The import message lists exactly what got filled in, so it's easy to spot-check.
  • If you open Compile without a Capture file handy, you can still add songs by hand on the Song List tab — importing isn't strictly required, just the normal path.

Reviewing and Correcting

Once a file is imported, work through it before exporting:

  • Check Event Details and Roles for anything that auto-filled incorrectly or needs a human's judgment.
  • If the file has more than one session, a Sessions section appears on the Song List tab — one card per session, with its own location and any officer differences. Each officer there has three real choices: use the Event default, set none for that role this session, or name a different person for just that session. Two sessions sharing a date, location, or label are still tracked separately — Compile disambiguates the display automatically rather than merging them.
  • Fill in anything that shouldn't burden someone logging live: the full memorial lesson write-up, business-session details, secretary's report, and similar long-form content belong on the Names & Lists and Business tabs.
  • Resolve any row flagged for a missing name or page, an unrecognized tunebook code, or a likely duplicate leader spelling (the Song List tab clusters similar spellings and lets you merge them to one canonical form).
  • Where possible, clear flagged items before exporting a final version — a proofing pass now is easier than a correction after publication.

Terminology and Abbreviation Systems

Non-default tunebooks need a short code assigned once, on the Song List tab's Book Handling section. EZ Minutes currently supports two independent code systems for this:

  • SingLoud.org Work Codes — used internally, and in every export except the dedicated SHMHA submission.
  • SHMHA abbreviations — used only in the SHMHA Minutes Book export, translated automatically from the SingLoud code you assign.

Neither system is more "correct" than the other — they're just the two published vocabularies the suite outputs today. Choosing the Type of output on the Preview & Export tab (Minutes Maker, SHMHA Minutes Book Submission, or Simple List) determines which applies, and the preview updates in real time, so you can check any of them before exporting.

Minutes Maker has its own per-song and summary-line checkboxes: show the song number, the title, both, or — if you uncheck both — Compile falls back to whichever one it actually has, rather than leaving a call-out with no identification at all. A song's source (tunebook) can also be shown on every call-out rather than only when it differs from the day's default book. None of this affects SHMHA Minutes Book Submission, which always applies its own fixed rule regardless of these checkboxes: printed-book songs are identified by page number only, and a title is used only when there's genuinely no page to give (an "Other" source).

Preview

Compile's preview on the Preview & Export tab represents the finished document as it stands right now. Any change you make — a correction on the Song List tab, a session's officer override, a different Type of output, a Minutes Maker checkbox, an opening-paragraph or prayer-phrasing choice — updates it immediately, so what you see is always current.

Exporting

Compile currently exports these formats, all available from the Preview & Export tab:

FormatTypical use
Plain textQuick copy into an email or document
MarkdownPosting to a website or wiki
HTMLReady to publish directly
PDF (print view)Opens your browser's print dialog — choose "Save as PDF"
Master CSVThe complete, authoritative project file — re-opens in either app without losing anything either one added
SHMHA Minutes BookMatches the Sacred Harp Musical Heritage Association's printed submission format exactly
Simple ListTerse, events-only list (officers, then each song's leader/page/source) for checking names and details, not publication

A Word (.docx) export previously existed but has been removed while its generator is rebuilt against the current data model — use plain text, Markdown, or HTML and paste into Word in the meantime.

Output profiles Partially implemented — Compile now has a "Type of output" choice on the Preview & Export tab (Minutes Maker, SHMHA Minutes Book Submission, or Simple List) that determines which wording options apply and which export formats make sense, separately from which file format delivers it. The fuller original vision — additional named profiles beyond these three, such as Website, Archival Record, or Data Exchange, each with its own structural rules — is still just an idea.

MP3 Chapters and Video Markers Planned — a future version may use the order and timing already captured to generate chapter lists for a long recording, YouTube-style timestamp markers, or editing cue sheets. Not available yet.

There is one master project file for an event, not a separate Capture file and Compile file. Capture creates the initial Master CSV; opening it in Compile and enriching it — corrections, business notes, session overrides, and everything else on Compile's tabs — produces an updated Master CSV that supersedes the one Capture made. That newest Master CSV is the current authoritative record; re-open it in either app to keep working, and treat earlier versions as backups or revisions rather than the "real" file. The other formats in the table above (plain text, Markdown, HTML, PDF, the SHMHA submission) are one-way publication outputs generated *from* the Master CSV — they're not meant to be re-opened or resumed, and none of them replace it.

Troubleshooting

Capture won't re-load my own CSV

Capture's own re-import is strict: the column headers and schema version have to match exactly, since it's designed to resume an in-progress session precisely. A file edited in a spreadsheet program can sometimes reorder or rename columns; re-export from Capture if possible.

A file won't import into Compile, or imports with almost nothing recognized

Compile is much more tolerant than Capture — it matches columns by name, recognizes several older/alternate column names, and will still import a file with only some recognizable columns, flagging what it found. If a file truly imports with nothing usable, check that it has at least a Leader/Caller, Page, or Notes column under some name Compile recognizes.

"Old schema" or version-mismatch message

This behaves differently in each app. Capture blocks importing a file from a different schema version outright, since it's designed to resume a session exactly. Compile is more tolerant: it flags the mismatch and asks you to double-check the result more carefully than usual, but the import still proceeds.

Missing or unknown tunebook code

Assign the book a SingLoud code on the Song List tab's Book Handling section. If the SHMHA export shows a code you don't recognize, check the SHMHA Guide tab's abbreviation table.

Browser storage unavailable

Capture will show a clear warning rather than silently failing to save. Download or copy your minutes right away if you see this, since local autosave isn't working on this device/browser combination.

Preview doesn't match what I expected

Check which Type of output is selected on the Preview & Export tab (Minutes Maker, SHMHA Minutes Book Submission, or Simple List) — they apply different style rules. Also check the Song List tab for a row that's still flagged (missing page, unresolved tag, or similar), since an unresolved row can print differently than a finished one.

DOCX export isn't available

Correct — it's been removed while it's rebuilt against the current data model. Use plain text, Markdown, or HTML and paste into Word in the meantime.

The instructional video won't load

It requires an internet connection once embedded. The written instructions on this page cover the same material and work offline.

I opened Compile without a Capture CSV

That's fine — you can add songs by hand on the Song List tab. Importing a Capture file is the normal path, not a requirement.
